Think first, then paint it exactly

For this example, a real Claude model paints the whole piece before the robot moves — not picking from a few code-written templates, but directly choosing every stroke's shape, color, and placement itself (see sim/llm_composer.py). The rationale below is the model's own unedited explanation of the composition it designed. The interactive demo above runs a deterministic, template-based client-side stand-in instead, since a static page with no backend can't make a real model call. The robot then reproduces the model's exact plan in NVIDIA Isaac Sim. Left: what the model painted. Right: the actual recorded simulation of a Franka Emika Panda arm, full body, painting that same plan via the RMPFlow motion controller — not a mockup; see sim/ in the repository for the pipeline that produced both.

“We built the whole piece around one unresolved teal arc that spirals up out of the lower-left and trails off into open air near the top right, like curiosity itself — a line that keeps searching instead of closing a shape. In the bottom-left corner, two separate blue strokes converge and then continue on as a single teal line, a quiet nod to Pittsburgh's three rivers meeting at the Point and turning into the visitor's favorite color. Lower right, a small orange figure reaches its arm toward a pink mark, a plain-spoken gesture for a robot built to help a person, while a thin purple loop up top and a few grounding black, brown, and green strokes keep the composition anchored without ever closing off the big teal gesture's room to wander.”
— Claude, painting for favorite color “teal”, city “Pittsburgh”, dream “to build robots that help people”, mood “curious”

How it works

  1. Kiosk input. A visitor answers a few short, personal prompts and picks a robot platform.
  2. Semantic composition. A real Claude model directly authors the piece — every stroke's own shape, pen color, and weight — from a small set of common pen colors (not custom-mixed paint) and one brush/tool it also chooses, up to 20 strokes. This page calls a small Cloudflare Worker backend that holds the model API key server-side (see worker/) and makes the real call; if that's unreachable, a fast deterministic local preview (ported from sim/composition.py, no model call) takes over instead, clearly labeled.
  3. Stroke planning. Each stroke is a smooth planar curve with a pen-up/pen-down state — the same representation the robot execution layer consumes.
  4. Robot-agnostic execution. The stroke plan is retargeted to the selected robot's task frame and physically executed. Validated so far in simulation (NVIDIA Isaac Sim, Franka arm) — see sim/ in the repository.

Full details are in the project's bilingual research proposal (not published in this repository). The sim/ directory has the Isaac Sim validation pipeline and the composition module this page is built on.
